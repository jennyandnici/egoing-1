# GitHub Issue (깃허브 이슈)

GitHub Issues는 프로젝트의 버그 추적, 기능 제안, 작업 관리 및 팀원 간의 소통을 위해 제공되는 협업 도구입니다.

## 1. 주요 용도
- **버그 리포트 (Bug Report)**: 발생한 오류나 결함을 기록하고 추적합니다.
- **기능 제안 (Feature Request)**: 새로운 아이디어나 추가할 기능에 대해 논의합니다.
- **작업 관리 (Task Tracking)**: 프로젝트의 할 일(To-do) 목록을 관리하고 진행 상황을 파악합니다.
- **토론 및 피드백 (Discussion & Feedback)**: 코드 및 프로젝트 방향성에 대한 의견을 나눕니다.

## 2. 주요 구성 요소
- **Title (제목)**: 이슈의 핵심 내용을 명확하고 간결하게 요약합니다.
- **Description (본문)**: 세부 내용, 재현 단계, 스크린샷 등을 마크다운(Markdown) 형식으로 작성합니다.
- **Assignees (담당자)**: 해당 작업을 진행할 사람을 지정합니다.
- **Labels (라벨)**: 이슈의 유형이나 상태를 분류합니다 (예: `bug`, `documentation`, `enhancement` 등).
- **Milestone (마일스톤)**: 특정 버전이나 마감일에 맞춰 여러 이슈를 묶어 관리합니다.

## 3. 커밋/PR 연동 (자동 종료 키워드)
커밋 메시지나 Pull Request 본문에 특정 키워드와 함께 이슈 번호를 적으면, 커밋이 기본 브랜치에 머지될 때 해당 이슈가 자동으로 종료(Closed)됩니다.
- 예: `Closes #1`, `Fixes #1`, `Resolves #1`
